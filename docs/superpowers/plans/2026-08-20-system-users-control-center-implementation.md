# خطة تنفيذ مركز تحكم المستخدمين الآليين

## المرحلة 1: البيانات والتوافق

- توسيع `system_user_settings` بإعدادات تاريخ الحضور والرد.
- توسيع قاعدة المعرفة الحالية بالنطاق والنوع والأولوية.
- إضافة جداول وصول البيانات والنشاط وطابور الردود.
- إضافة ensure-block غير هدّام لقواعد البيانات الحالية.
- إضافة مخططات تحقق وفهارس وقيود فريدة.

## المرحلة 2: خدمات الخادم

- بناء سجل ثابت لمصادر البيانات والجداول والحقول الآمنة.
- بناء خدمة توليد ومعاينة الحضور التاريخي مع قفل لكل مستخدم.
- بناء تسجيل نشاط ذري مع تغييرات الإعدادات والمعرفة والوصول.
- دمج المعرفة المكونة من طبقتين ومصادر البيانات الممنوحة في سياق المحاكي.
- تحويل الردود الفورية إلى طابور دائم يحترم وقت وفئة الرد.

## المرحلة 3: API والصلاحيات

- توسيع مسارات إعدادات المستخدمين الآليين.
- إضافة CRUD المعرفة، وصول البيانات، الحضور التاريخي، والنشاط.
- تقييد الجداول المتقدمة والحضور التاريخي بصلاحية `admin`.
- إبقاء قراءة قاعدة المعرفة القديمة مؤقتًا وإيقاف كتابتها.

## المرحلة 4: الواجهة

- إعادة بناء تبويب مستخدمي النظام كمركز تحكم متجاوب RTL.
- إضافة أقسام التشغيل، المعرفة، الحضور، المراسلات، البيانات، والنشاط.
- نقل واجهة قاعدة المعرفة وإزالتها من مركز خدمة العملاء.
- توفير معاينة صريحة قبل إنشاء الحضور التاريخي.
- إظهار إعدادات الجداول المتقدمة للمدير فقط.

## المرحلة 5: التحقق

- اختبارات مخططات البيانات والصلاحيات والخصوصية.
- اختبارات توليد الحضور ومنع التكرار.
- اختبارات جدولة الردود وقيود الوقت والفئة.
- TypeScript وفحص حجم الملفات و`git diff --check`.
- إعادة تشغيل التطبيق وفحص السجلات والواجهة الفعلية.
- مراجعة كود مستقلة وإصلاح أي ملاحظات مانعة.
